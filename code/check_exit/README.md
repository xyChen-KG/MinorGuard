# 未成年人模式退出保护

本任务的入口、场景、提示词、采集、判断、报告、配置和测试都在本目录。
默认执行真机动态测试。加 `--static` 可复用原时长检查的 APK 校验与 JADX 工具，筛查从替代入口退出模式或进入受限页面的路径。

## 使用

在项目 `code/` 目录运行，继续复用已有 `.venv` 和 `.env`，不新建密钥文件。

```bash
# 先检查：不截图、不改变页面、不调用付费模型
.venv/bin/python -m check_exit --package com.dragon.read --check

# 实际测试：会启动App、导航、可能设置模式独立密码、重启App及最后退出模式
.venv/bin/python -m check_exit --package com.dragon.read

# 多设备时指定已连接设备；已有模式密码只有明确确认为全1时才加此标志
.venv/bin/python -m check_exit --package com.dragon.read --serial IP:连接端口 --existing-pin-all-ones

# 禁止设置新模式密码
.venv/bin/python -m check_exit --package com.dragon.read --no-setup
```

请使用受控测试账号，提前解锁手机并完成登录，测试期间不要手动操作手机或完成指纹/人脸验证。ADB 的配对/连接仍须事先完成。

首版准备阶段只自动设置/确认新模式密码；若重新开启模式要求验证已存在的旧密码，请先由用户开启模式再运行。`--existing-pin-all-ones` 只授权最后的正确密码退出对照，不授权负向测试或未知密码尝试。

模型配置复用 `TYPESAFE_API_KEY`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`；最终判定还支持已有 `CHECK_LLM_*` 覆盖。密码工具仍使用 `LLM_*`。
默认最终判定显式发送 `thinking.type=enabled`、`reasoning_effort=high`，不自动降级或付费重试。Jev无置信度执行门槛。

### 静态旁路扫描

```bash
# 校验同版 APK，扫描候选，再做三个动态场景
.venv/bin/python -m check_exit --package tv.danmaku.bili --static

# 只扫描候选：从手机读取已安装 APK
.venv/bin/python -m check_exit --package tv.danmaku.bili --static-only

# 只扫描已有 APK：无需连接手机，包名和版本从 APK 读取
.venv/bin/python -m check_exit --static-only --apk ../apks/bilibili/bilibili.apk
```

静态分析沿用 `check_config.json` 的 JADX 服务和分析预算，可通过 `--analysis-config` 指定另一份配置。先核对输入 APK 的哈希、包名、版本与 JADX 当前项目，再从 Manifest 筛选最多 40 个入口做源码追踪。使用手机的流程还会校验其安装文件。候选要引用实际读取的源码，报告保留覆盖范围和未查清的路径。

静态分析优先从模式状态修改点反查调用者，并从入口正向追踪校验和条件。模型可以用 `record_lead` 记录重要线索，结束前如有待查线索会提醒一次，仍可在说明缺口后提交。报告显示待查或受阻的线索，完整线索存放在静态结果中。模型输出是辅助分析，代码只核对引文出处，调用链的语义仍需结合源码核对。

`--static` 可附加最多三个 `--replay-uri`，用来指定已审阅、可在测试机上打开的完整深链接。程序要求链接出现在候选源码引文中、匹配声明的无权限导出入口，并由手机实际解析到该入口。首版重放支持简单的 scheme、host、path 或 pathPrefix 匹配。复杂过滤条件、参数链接及分享或通知的内部触发链保留待人工验证。

复测安排在重启后的模式开启确认与正确密码对照之间。每条保留起点、触发后首张图和最终状态图，复测判定与三个原有场景分别记录。若复测后模式已关闭或状态不明，保留现场并跳过正确密码对照。运行目录中的 `static/` 保存候选、入口清单和源码证据，整合报告在运行目录根部。

## 固定流程

1. 准备：确认模式开启；必要时按页面明确长度设置独立测试密码（4/6位全1）。未知旧密码、身份核验交给用户。
2. S1：实际点击退出入口，不输入密码，遇到密码页返回，重新采集明确的模式状态。
3. S2：仅结束当前被测App进程并重新启动，检查模式状态。不重启手机、不清数据、不卸载。
4. S3：最后才用本轮设置或用户明确确认的全1密码，做正确密码退出对照。
5. 将全部已保存原始截图、完整动作记录和场景执行状态交给 DeepSeek，最终判断、证据引用和局限由其给出。

Jev的状态描述仅用于导航和阶段推进，不是最终结论。若前置场景不完整或观察到模式已关闭，就保留结果、跳过依赖场景，不悄悄重新开启模式来补齐。没有发现必须动作、状态图不明确时不会把该阶段记为采集完成。

### 分层与分阶段

业务阶段由代码调度，每次Jev请求只包含当前子阶段的目标、完成条件、可用动作和相关问题。共用的只有基本操作约束，不再把整个退出测试流程放进同一份导航提示词。

| 业务阶段 | 代码控制的子阶段 |
| --- | --- |
| 准备 | 进入设置 → 找到模式专页 → 处理开启页协议复选框 → 开启 → 专用密码工具（如需）→ 核对已开启 |
| 不验证退出 | 点击一次退出 → 记录密码/验证页面并返回 → 进入设置 → 找到模式专页 → 只读取状态 |
| 重启后检查 | 代码重启目标App → 进入设置 → 找到模式专页 → 只读取状态 |
| 正确密码对照 | 点击一次退出 → 确认密码页面 → 专用密码工具 → 进入设置 → 找到模式专页 → 只读取状态 |

已在模式专页时，进入设置/寻找入口的阶段可直接确认到达，不强行返回设置。已开启时跳过开启与新密码设置。开启页协议勾选仅在用户已授权的准备阶段处理，不证明监护人身份或法律上的有效同意。

寻找入口时若已到开启模式的验证/使用限制密码页，程序停止，不把它当作未完成的新密码设置反复返回。状态不明时最多返回两次。宵禁等页面可能挡住正常退出入口，当前版本会报告场景受限，不在负向测试前擅自输入密码解除限制，也不把继续使用授权当成退出模式。

例如“找模式页”不提供开启、退出或密码动作；最后“读取状态”只有等待、请求推进、停止选项，不提供点击框和滑动问题。点击类别直接编码在动作选项中，避免“是否点击”和“按钮用途”两个独立问题互相冲突。Jev可以请求推进，但代码核对本阶段的页面和实际动作后才切换，不能只靠模型一句完成跳过退出操作。

阶段定义和提示词在 `stages.py`，请求构造在 `navigator.py`，动作/切换/证据在 `collector.py`。`trace.jsonl`和截图元数据包含stage，场景文件包含各子阶段记录，`prompt_snapshot.json`保存本轮各阶段实际提示词。默认流程不调用 APK 分析。

### 重复操作脱困

连续3次同类操作且截图主体几乎不变、连续6次同类操作（避免在无限内容流中一直翻页），或检测到返回原页面的交替循环时，暂停Jev，临时交给DeepSeek。截图差异忽略状态栏；它只是导航停滞线索，不是模式或安全结论。

DeepSeek读取最近3张原始截图、实际动作和当前子阶段，最多执行3个导航动作。点击时由DeepSeek描述具体可见控件，再由Jev单独检查可见性并返回精确框；DeepSeek的参考坐标不直接用于真机点击。必须在操作后的截图中确认到达可继续探索的新页面，才能带下一步提示交回Jev。不能仅凭广告变化、请求成功或一句“已脱困”交回。接管不跳过阶段、不直接完成场景，也不裁决App是否存在绕过。Jev未达阶段条件便提前停止且不涉及身份验证时，也可触发有预算的复核。

两位导航器共用操作执行和阶段限制；负向阶段仍禁止密码工具和输入，重启检查不能重新开启模式。接管使用已有LLM_*接口，显式开启enabled/high，不添加密钥或独立常驻Agent。每轮最多4次接管，共享总时间、动作、阶段动作及80次采集请求预算；达到预算或API失败保留证据并停止，不无限重试。

密码工具也使用分工：Jev单独识别4/6位输入槽，密码模型只决定设置/确认/解锁及输入方式，数字键、输入区域和提交按钮统一由Jev重新定位。代码按实际识别的位数输入固定全1值，不直接采用密码模型猜测的位数和坐标。任何负向阶段都不能调用这一分支。

模式开启表单也可能同时包含密码框和其他资料，不要求页面只能被识别为介绍页。填写密码后，若系统确认键盘仍显示，程序收起键盘再让模型检查提交按钮。出生年月、家长手机号等资料不在密码工具的自动填写能力内，需提前准备。只设置一次密码、没有二次确认页的App，也必须等到明确开启状态后才把本轮测试密码记为可用于退出对照；确认步骤中断时不会记为已知密码。

退出密码页时，第一次返回可能只收起系统键盘。负向流程会继续观察并返回（最多3次），直到截图确实离开密码页才推进，不能把一次ADB返回成功当成已离开。

## 安全与边界

- no_auth/restart 阶段在设备/采集两层禁用密码委派、输入及密码工具点击。识别为密码页时只记录并返回。只有prepare允许设置/确认，positive允许已知密码解锁。
- 密码不猜测、不自动重试；发生错误/部分输入失败停止。模式测试密码不用于账号、设备或支付密码。
- 截图传输或PNG解码失败时只重读截图一次，不重复前一步点击、密码输入或重启；再次失败保留“操作已执行但后置截图缺失”，停止并输出不确定，不能把传输故障认定为App禁止截图。
- 截图内容区完全黑屏时，若Android窗口信息同时确认被测App在前台且带SECURE标志的输入法窗口确实可见，程序只执行一次返回收起键盘，再采集页面；原黑屏和恢复后的截图都会保留。该处理不修改安全键盘设置、不盲输密码。收起后仍全黑则停止；每轮最多8次。正常可读页面不会触发它。
- 图片识别仍可能误判，屏幕坐标点击的操作性质依赖模型识别，不能承诺仅靠截图就能提供绝对安全边界。未知身份验证、锁屏、验证码应停止。
- 普通点击前读取Android窗口焦点和系统导航栏边界：目标在系统导航栏时阻止点击并触发脱困；确认已离开被测App时最多重新打开目标App两次，不把重新打开计成退出尝试。厂商窗口信息读取不完整时仍有识别局限。
- 首版不做错误密码、找回密码、清数据、卸载、系统时间修改；没有常驻规划/审核Agent。临时导航接管会明确打印并记录在trace.jsonl和最终用量统计中。
- “本轮未发现绕过”只覆盖两个已执行负向路径，且需要正确密码对照成功；不是对全部绕过路径的证明。静默授权、系统验证等不可观察因素应在判定中说明。
- 最终判断只有一次，不额外调用审核Agent；代码只核查输出格式、场景覆盖、必要动作和引用完整性，不替模型裁决截图语义。
- 正常测试会改变模式状态，可能设置全1弱测试密码。不要在生产账号长期保留该测试密码；程序不会自动恢复原状态。截图可能包含个人信息，不要公开原始结果目录。

## 输出

配置中的相对路径相对于本目录，默认写入仓库根的 `results/check_exit/运行编号/`：

```text
images/              原始有序截图；*-tap.png为独立标注副本
trace.jsonl          带T编号的实际操作与导航观察
images.json         截图ID、哈希和导航观察
scenarios.json      准备及三个场景的执行情况
collection.json     最终模型收到的完整证据元数据（不含图片base64）
prompt_snapshot.json 实际提示词
run_config.json     非密钥配置
result.json         执行状态、模型判断、用量和时间
judge_response.json 最终模型的简短JSON答案（便于检查被拒绝的引用/状态，不含原始思考或图片base64）
reference_index.json 从真实操作记录提取的各场景前后图片、退出/重启及密码输入事件编号（不包含合规判断）
report.md           简短报告及证据链接
```

API失败、预算耗尽、未找到入口或中断都保留已有证据，不视为App不合规。原始思考内容、API Key和图片base64不落盘。普通程序异常可输出报告；系统断电/强制杀进程不保证最终报告完成。

默认采集60个动作、80次导航/密码/脱困请求、600秒；最终判定另有最多300秒。ADB单个操作有自身超时，外层预算不是操作系统硬实时中断。图片数量、编码体积或模型请求超限时显式报错，不静默删除部分证据。

```bash
.venv/bin/python -m unittest discover -s tests -v
```

离线测试使用合成图片、假设备和假模型，不代表真实App通过，也不测Jev/DeepSeek的真实准确率。
